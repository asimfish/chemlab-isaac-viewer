# ADR-006: Use the existing5090 for outbound training-job relay

Status: Accepted for the bounded live retest, following the owner request.

The previous private-network gateway was a stopped2GPU development machine. Its startup was denied by a personal-NAS quota check in another resource zone. Restoring it would allocate additional cards.

| Candidate | Benefit | Cost / evidence |
|---|---|---|
| Restore original development gateway | Existing private route | Startup denied; allocates2extra GPUs |
| Connect5090 directly to a training pod | Simple forwarding |5090 is outside that pod subnet; no working direct route established |
| Training job initiates reverseSSH to5090 | Reuses an existing CPU relay without another GPU allocation | Requires a bounded, authenticated outbound SSH client and fixed reverse ports |

The third route is selected and verified with the actual owned job. The source client generates an ephemeral private key inside its own container and never uploads it.5090 receives only the public key with `restrict`, a false forced command, fixed `permitlisten` loopback ports and an expiry. Local forwarding is limited to an unused loopback discard destination. Tests demonstrate permitted reverse echo, denied foreign port, denied shell, and exact public-key removal. Host-key verification uses the key obtained over the existing trusted SSH connection. OpenSSH8.9 uses server-local expiry times;5090 uses UTC. The key and owned units are removed/stopped at the session deadline. Existing server SSH configuration and unrelated keys/processes are preserved.

Media remains original H264 over framed UDP/TCP inside SSH. The private GitHub forwarding edge continues to authenticate the viewer and strip browser credentials before upstream forwarding. CDP/signaling and health endpoints remain on loopback; the loopback health endpoint returns only fixed owned-session state. The browser bridge still runs on the workstation; this is not a claim that5090 is a new public HTTP server.

The package pipeline now tests the actual tar artifact through the full CPU reverseSSH lifecycle before upload, rather than testing an unbound source directory. A separate hash check binds the uploaded archive to the expected content. Rollback is to let this finite session expire, remove its exact public key and stop only its task-owned services. No generic policy or storage-quota bypass is introduced.

The SSH option semantics follow the [OpenSSH sshd authorized-key documentation](https://man.openbsd.org/sshd.8); the deployed8.9 expiry syntax was verified against its installed manual and a live expiring-key canary.
