# ADR009: native H264 WebRTC and domestic TURN candidate

Status: experimental CPU gate passed; production switch pending reachable domestic UDP endpoint and native GPU acceptance.

Requirement: keep the complete official Isaac GUI and203asset scene while targeting60fps and100–150ms interactive feedback on the owner's network. The measured native GitHub route remains roughly595ms click-to-visible including150ms held click; transport changes must be measured separately from Isaac rendering. The old pipeline is retained.

Candidates: (A) keep the current GitHub video/control WebSocket; it works but the public RTT is roughly285ms and can dominate interaction. (B) use original-H264 WebRTC/SRTP plus an ordered input data channel; keep GitHub for authenticated signaling only. Direct ICE may fail at NAT boundaries, so use an owned domestic REST-authenticated TURN server when necessary. (C) another Cloudflare quick tunnel was only a constant CPU probe; its selected LAX edge does not establish a faster route and it was not promoted.

Decision: prepare B as an isolated candidate, require a measured reachable domestic relay before GPU retesting, and retain A. aiortc packetizes AVPacket input without a second video encoder. Session-bound HMAC TURN credentials, DTLS media, fixed loopback native upstream, bounded sessions/queues and the existing private GitHub edge define the boundaries. Signaling can close after ICE connects without ending media/control. An independent upstream heartbeat fixes an initial180second idle-close issue detected in the CPU lab.

Evidence: direct60fps CPU input p50/p9528.4/35.6ms; forced authenticatedTURN38.0/58.9ms; localWebSocket34.8/36.1ms, all10/10 after3warmups. Forced relay remained60fps/zero loss/drop/freeze185seconds. Wrong credentials rejected;12candidate plus26core tests pass. These are loopback CPU protocol results, not native GPU or owner-WAN speedups. Cross-network5090/workstation ICE failed despite srflx candidates. The existing5090 SSH ingress terminates at a private network; no public UDP mapping is evidenced. Missing: an owned domestic publicIPv4/UDP relay, followed by native60fps and WAN interaction/recovery acceptance. GPU006 providerSucceeded, exact key/relay cleanup completed, no new allocation.

Risks retained: AVPacket passthrough cannot itself generate a new hardware keyframe on PLI; upstream keyframe/reconnect recovery needs actual lossy-WAN validation. The CPU trial uses a locally extracted old coturn package only on loopback; deployment must select a maintained host package. No candidate has replaced the user-visible native gateway.
