# ADR008: per-viewer camera direction and bounded pending motion

Status: deployed to the bounded renewal006 gateway; independent review pending.

Owner reports camera dragging feels reversed and latency remains high. A captured native trace preserves the original direction, so keep native behavior by default and offer vertical/horizontal/both-axis preference per viewer. Reflect SDK absolute cursor coordinates around the camera-gesture anchor together with relative deltas. A relative-delta-only candidate failed real image verification because this SDK uses absolute pointer messages. Apply only to native video right-drag or Alt+left-drag, including release; leave ordinary GUI clicks/drags unchanged. Restrict server mode values to a four-item enum and keep producer injection on private loopback CDP.

The CDP input consumer needs about16.7ms per move. Replace only adjacent pending mouse moves within the same buttons/modifiers; all transitions remain FIFO barriers. An exhausted transition queue closes the session rather than silently dropping input. The stream reports queue depth/coalesced counts. Preserve H264 reference-frame ordering. Backlog replay and a real GitHub burst pass; idle native-click latency does not improve. Direct routing remains selected after interleaved comparison. Rollback is the preceding source commit plus restarting only the bounded task gateway; no GPU recreation is needed. Session expiry/authentication/Host/Origin restrictions remain enforced.

Evidence: benchmarks/interaction006.json,24Python regressions,JavaScript event-coordinate tests,private opposite-camera images and source-spec restoration receipt. See PERFORMANCE.md for complete metrics and limits.
